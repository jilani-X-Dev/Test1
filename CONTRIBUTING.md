# Contributing

Thanks for helping improve GitHub Workflow Test Lab.

## Ground rules

- Keep changes focused and reviewable.
- Describe the reason for each change.
- Never commit passwords, API tokens, private keys, or other secrets.
- Prefer accurate documentation over activity created only to inflate metrics.

## Suggested workflow

1. Check existing issues before starting.
2. Create a branch from `main`, such as `docs/clarify-setup` or `fix/readme-link`.
3. Make the smallest useful change.
4. Run the checks listed in [TESTING.md](TESTING.md).
5. Open a pull request with a clear summary and link a related issue when applicable.
6. Review the diff and resolve any feedback before merging.

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] Markdown and links were checked.
- [ ] No credentials or unrelated files were added.
- [ ] The PR description explains what changed and how it was verified.
